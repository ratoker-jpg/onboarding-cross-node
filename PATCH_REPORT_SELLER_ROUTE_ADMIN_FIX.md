## 4. Как теперь работает создание ключа
- Админ вводит `Фамилия`, `Имя`, выбирает сегмент и направление.
- Backend собирает `ФИО = Фамилия + Имя`.
- В `Новички` сохраняются:
  - `key`;
  - `ФИО`;
  - `Фамилия`;
  - `Имя`;
  - `сегмент`;
  - `направление`;
  - стартовые поля маршрута (`старт`, `текущий_день`, `статус_текущего_дня` и др.).

## 5. Как теперь определяется seller/default route
- Если `сегмент` содержит `Селлеры`, backend строит `routeVariant = seller`.
- Для всех остальных сегментов используется `routeVariant = default`.
- Фильтрация блоков второго дня теперь идёт через колонку `route_variant` в `Блоки_дня`.

## 6. Как изменён день 2 для селлеров
- Общие блоки второго дня остаются доступными по пустому `route_variant`:
  - `d2_intro`;
  - `d2_online_accounting`;
  - `d2_checkpoint`.
- Только для обычного маршрута показываются:
  - `d2_edo`;
  - `d2_transport_edo`;
  - `d2_iiz`;
  - `d2_amber`.
- Только для seller-маршрута показывается:
  - `d2_mpstats`.
- Для MPStats добавлен отдельный материал и кастомная кнопка `Открыть курс MPStats`.

## 7. Как работает preview day selector
- Frontend теперь передаёт выбранный day в `getPreviewState`.
- Backend больше не подменяет только число дня поверх чужого state, а собирает полноценный state под выбранный day.
- Это устраняет старую ситуацию, когда при выборе day 1 мог открываться state day 3.

## 8. Как работает seller/default preview
- В preview добавлен select варианта маршрута.
- Для day 2:
  - `default` даёт ОБ + default-блоки дня 2;
  - `seller` даёт ОБ + MPStats.
- Preview по-прежнему не должен писать progress/help/material sessions, потому что backend строит preview state без реального progress/session контекста, а frontend блокирует сохранения.

## 9. Как теперь собирается карточка новичка по всем дням
- Backend собирает `dayHistory` по всем дням из:
  - `Прогресс`;
  - `Сессии_материалов`;
  - `Помощь`;
  - `Отслеживание_прохождения`.
- Frontend рендерит по каждому дню:
  - статус дня;
  - required blocks summary;
  - список material sessions;
  - список вопросов;
  - последние события.

## 10. Как считается время на материалах
- Основной источник: `duration_min`.
- Fallback: `duration_sec / 60`.
- Для открытых незавершённых сессий используется fallback от `opened_at_*` до текущего времени, чтобы не терять open sessions в админской карточке.
